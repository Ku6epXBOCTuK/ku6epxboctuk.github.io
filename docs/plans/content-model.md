# Модель контента и процесс создания

> Статус: на ревью. Один из трёх планов: дизайн, модель контента, автоматизация.
> Этот — базовый: определяет типы контента, схемы frontmatter и процесс работы с
> ручным контентом. Обновлено по итогам ревью: старт с нуля без миграций (старые
> статьи чисто текстовые — при желании просто копируются руками), добавлена
> схема двуязычности статей.

## Решено по итогам ревью

Открытые вопросы из прошлой версии закрыты:

1. **`/posts`** — отдельная страница; на главной блок «последние посты», причём
   **количество настраивается** (конфиг `HOME_RECENT_POSTS`, дефолт 3) — см.
   план дизайна.
2. **`type` у проектов убирается.** Остаются `subtitle` (короткое описание) и
   свободный массив `tags` — старый enum не тащим, новые категории задаются
   тегами на лету.
3. **Черновики:** в dev видны с бейджем «draft», в production скрыты; в
   автопостинг не попадают.
4. **Переводы:** в соцсети уходит только основной язык, перевод не постится
   никогда. Добавление перевода — визард `new article <slug> --lang en`.
   Непереведённые статьи ничего не ломают.
5. **Чип-переключатель ru/en** — интерфейс планируем и делаем сейчас, контент
   переводов — по мере готовности.

## Цель

Перейти к четырём типам контента с разной степенью автоматизации. Сайт
перезапускается с нуля: старые форматы (`tag` строкой, `apr 2026`, excerpt) не
поддерживаются, но специального миграционного процесса нет — старые статьи чисто
текстовые, любую можно просто скопировать в новую папку (см. «Перенос старых
статей»).

| Тип        | Что это                                      | Как создаётся       |
| ---------- | -------------------------------------------- | ------------------- |
| `posts`    | короткие посты (формат твиттер/телеграм)     | вручную, визард     |
| `articles` | большие статьи с картинками и кодом          | вручную, визард     |
| `projects` | описание проектов: картинка, исходники, демо | скрипт из README    |
| `weekly`   | автогенерируемые отчёты о недельной работе   | скрипт из git-логов |

Руками создаются только посты и статьи. Проекты и weekly — автоматические
(скрипты описаны в плане автоматизации); здесь фиксируются только их схемы.

## Типы контента

### 1. `posts` — короткие посты

Формат твиттер/телеграм: небольшой текст, опционально картинка и/или ссылка.
Папка: `src/posts/` (имя сохраняется).

```yaml
---
title: короткий заголовок
date: 2026-09-08
tags:
  - svelte
image: images/2026-09-08.jpg # опционально
link: https://example.com # опционально, внешняя ссылка
draft: true
---
текст поста. небольшой. без структуры заголовков.
```

- body и есть контент — целиком уходит и на сайт, и в соцсети (без
  `<!--more-->`, в отличие от статей);
- `image` — картинка к посту (для сайта и для соцсетей);
- `link` — если пост «про что-то снаружи» (релиз, чужая статья).

### 2. `articles` — большие статьи

Полноценные статьи с картинками, кодом, таблицами. Обязательна короткая версия,
показываемая «до полного открытия». Папка: `src/articles/` (новая).

```yaml
---
title: The Entity Component System
date: 2026-04-15
lang: ru
tags:
  - engineering
  - gamedev
image: images/ecs-cover.jpg # опциональная обложка
draft: true
---

вступление — короткая версия статьи.

<!--more-->

полный текст статьи: разделы, картинки, код, таблицы...
```

- единый источник короткой версии — маркер `<!--more-->` в body (отдельное поле
  excerpt не вводим — убираем дублирование);
- список статей и превью показывают текст до `<!--more-->` + блок «читать
  дальше»;
- `prepare-post.ts` уже умеет резать по `<!--more-->` — переиспользуется;
- поле `lang` и пары переводов — см. раздел «Двуязычность статей».

### 3. `projects` — проекты

Описание проекта: картинка, ссылка на исходники, ссылка на живой проект (если
есть). Папка: `src/projects/` (имя сохраняется).

```yaml
---
title: now-playing
subtitle: obs browser source
description:
  obs browser source widget that displays the currently playing track.
tags:
  - html
image: images/now-playing.jpg
repo: https://github.com/Ku6epXBOCTuK/now_playing # исходники
demo: https://ku6epxboctuk.github.io/now_playing # живой проект, опционально
icon: ✦ # эмодзи/символ для иконки проекта, опционально (по умолчанию ✦)
color: periwinkle # акцент иконки: coral / periwinkle / sky (по умолчанию coral)
status: ready
synced_at: 2026-09-08
draft: false
---
```

- `url` переименовывается в `repo`, добавляется `demo` (может отсутствовать);
- `status`, `synced_at`, `description` обслуживаются скриптом синхронизации из
  README (план автоматизации), остальное — вручную.
- `icon` — эмодзи/символ в квадратной иконке проекта (по умолчанию `✦`); `color`
  — акцент иконки: `coral` / `periwinkle` / `sky` (по умолчанию `coral`).
  Приходят из `projects.yaml` (план автоматизации), показываются на карточке
  проекта и в hero.

### 4. `weekly` — автоматические отчёты

Недельные отчёты о работе. Генерируются скриптом из git-истории проектов,
вручную не создаются вообще. Папка: `src/weekly/` (имя сохраняется).

```yaml
---
title: weekly 2026-W37
date: 2026-09-07 # понедельник недели
excerpt: 4 проекта, 23 коммита. now-playing: v1.2, git-overhooks: hooks api.
generated: true
generated_at: 2026-09-08T10:00:00Z
---
```

- `generated: true` — явная пометка автогенерации (для UI и линтера);
- генерация, формат body и запуски — в плане автоматизации.

## Сквозные решения

- **Даты — ISO `YYYY-MM-DD` везде.** Старый формат `apr 2026` не сортируется и
  блокирует weekly-автоматику. Человекочитаемый вид (`apr 2026`) формирует UI.
- **`tags` — всегда массив.** Поле `tag` (строка, разделённая пробелами)
  удаляется. Единообразно для всех типов.
- **`draft: true|false` — у всех типов.** В production-сборке черновики не
  попадают на сайт и в автопостинг; в dev — видны (предпросмотр) с бейджем
  «draft» в углу карточки.
- **Сортировка списков по дате, свежие сверху** (`src/lib/*`).

## Двуязычность статей (продумать заранее)

Требование: статьи могут существовать на двух языках (русский + английский),
причём не у всех статей будет перевод. Решение должно работать и для ручного
письма, и для автопостинга, и не потребовать переделки потом.

Выбранный подход — суффикс языка в имени файла:

```txt
src/articles/
  ecs-deep-dive.md        # ru — основной язык, суффикс не нужен
  ecs-deep-dive.en.md     # en — перевод той же статьи
```

- поле `lang: ru|en` в frontmatter; дефолт `ru` — можно не указывать;
- пара связывается по базовому имени: `X.md` ↔ `X.<lang>.md`;
- в списке статей — одна карточка; если есть перевод, на странице появляется
  чип-переключатель ru/en (интерфейс чипа — в объёме сейчас, контент переводов —
  по мере готовности); непереведённая статья показывается как есть;
- визард: `npm run new article ecs-deep-dive` создаёт основную статью,
  `npm run new article ecs-deep-dive --lang en` — файл перевода с
  подсказкой-шаблоном;
- автопостинг: в соцсети уходит только версия основного языка, перевод не
  постится никогда;
- weekly и posts — только на основном языке;
- URL: `/articles/ecs-deep-dive` и `/articles/ecs-deep-dive.en` — работает на
  GitHub Pages без i18n-роутинга; если позже понадобится `/en/articles/...` —
  добавим редиректы, схема файлов не меняется.

Почему не папки `src/articles/en/`: раздельные списки в lib-хелперах и
frontmatter-схемах, легче потерять синхронность пар. Суффикс держит пару рядом в
одной папке — видно, что переведено, а что нет.

## Процесс создания ручного контента (визард)

Проблема: чтобы написать пост/статью, нужно зайти в папку, создать файл среди
других, вручную набрать frontmatter, не забыть `<!--more-->` для статьи.
Решение: CLI-визард `scripts/new-content.ts` (tsx, без новых зависимостей).

```bash
npm run new                        # интерактивный визард
npm run new post my-thought        # быстрый режим: пост
npm run new article ecs-deep-dive  # статья с шаблоном и <!--more-->
```

Поведение:

1. **Тип**: post / article (projects и weekly визард не создаёт — у них свои
   автоматические процессы).
2. **Slug**: валидация на лету (`a-z0-9`, `-`), проверка что файл не существует.
   Для статьи — опция `--lang en` (создаёт файл перевода `slug.en.md`, см.
   «Двуязычность статей»).
3. **Вопросы по типу** (все с дефолтами, Enter — принять): post — теги, link,
   image; article — теги; общие — title (дефолт из slug).
4. **Создание файла** по шаблону типа: дата — сегодня (ISO), у статьи сразу
   вставлен `<!--more-->` с подписью-подсказкой, что выше тизера. Это снимает
   главный источник ошибок автопостинга.
5. Сообщение «файл создан: <путь>» — дальше редактор и Frontmatter CMS
   (обновлённые схемы дают там те же поля; CMS остаётся вторым путём создания).

Черновик живёт рядом с контентом (`draft: true` в самом файле) — никаких
отдельных папок черновиков, путь публикации не меняется.

## Старт с нуля и перенос старых статей

Папки контента стартуют пустыми:

- `src/posts/`, `src/projects/`, `src/weekly/` — очистить от старых файлов (в
  weekly оставить `.gitkeep`);
- `src/articles/` — создать пустой;
- наполняем сразу по новым схемам: первый пост/статья создаются визардом,
  проекты — через `sync:projects` после заполнения `projects.yaml`.

Старые статьи чисто текстовые, поэтому отдельный процесс переноса не нужен: если
какую-то захочется оставить на сайте, файл просто копируется в `src/articles/`,
и у него руками правится frontmatter под новую схему (дата в ISO, `tag` → массив
`tags`, при желании `<!--more-->` после вступления) — пара минут на статью.
Никаких миграционных скриптов; решается по ходу, статья за статьёй, а не все
сразу.

Старые решения, которые не тащим дальше: `tag` строкой, `excerpt` в frontmatter
статей, даты `apr 2026`, поле `url` у проектов.

## Изменения в кодовой базе

- `src/articles/` — новая папка (стартует пустой; старые статьи копируются
  руками по желанию, см. «Перенос старых статей»).
- `src/lib/posts.ts` → разделить: `lib/articles.ts` (с группировкой пар ru/en),
  `lib/posts.ts`, `lib/projects.ts` (обновлённый), `lib/weekly.ts`; общий хелпер
  `lib/content.ts` (glob + frontmatter + фильтр draft + сортировка).
- Роуты: `/articles` (детальная `/articles/[slug]`), `/posts`, `/projects`,
  `/weekly`; навигация: home / posts / articles / projects / weekly.
- `frontmatter.json` — новые схемы типов (post, article, project, weekly),
  pageFolders: articles, posts.
- `scripts/lint-content.ts` — схемы под 4 типа: ISO-даты, массив tags,
  `<!--more-->` для статей, `generated: true` для weekly, `lang` ru|en.
- `scripts/prepare-post.ts` — CONTENT_DIRS + шаблоны: post (весь body), article
  (тизер до `<!--more-->`), project (description), weekly (excerpt).
- `scripts/templates.json` — url-шаблоны: `/articles/{slug}` для статей;
  добавить шаблоны для post и weekly.
- `.github/workflows/publish.yml` — триггер на `src/articles/**`,
  `src/posts/**`.
- `scripts/new-content.ts` + npm-скрипт `new` — визард (с опцией `--lang`).
- `docs/writing.md` — «как написать пост/статью и что произойдёт после пуша».
