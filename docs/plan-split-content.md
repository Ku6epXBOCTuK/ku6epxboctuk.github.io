# План: разделение хранения контента

Данные переезжают из frontmatter в три файла на единицу: переводимое остаётся в
`index.<lang>.md`, общее уходит в `<type>s.json`, локальное — в
`<type>s.local.json`.

Обратная совместимость не нужна: контента на сайте нет, схема меняется целиком.

Редактор при этом не должен знать, что где лежит. Он видит склеенный `Entry`,
отдаёт его же на сохранение, а раскладку по файлам делает репозиторий.

**Состояние: выполнено полностью, фазы 1–8.** Документ остаётся как объяснение
«почему так», а не как список дел. Что фактически вышло и где план разошёлся с
реальностью — в разделе «Что вышло» в конце.

## Решения

**Картинка — в json, одна на оба языка.** Сейчас это упрощение: одна картинка
вместо двух. Но решение не должно упираться в `saveEntry` и `loadEntry`, поэтому
переезд `image` обратно в md позже — это смена флага `scope` у одного поля и
правка склеивания. Ничего больше трогать не придётся, и это главная причина
закладывать репозиторий именно так. Подробности — в разделе «Расширяемость».

**`needs_translation` — per-lang, в md.** Это факт о конкретном переводе, а не о
единице контента.

**`isMock` — выкинуть.** Поле скрыто (`hidden`), существует только для
генератора моков; генератор переписывается в фазе 7.

**`weekly` обзавести `weekly.json`.** Он генерируется, а не редактируется, но
для единообразия схема у него та же.

**`icon`, `color`, `synced_at` — в `projects.json` как shared.** Сайт их читает
(`src/lib/projects.ts:29-35`), а в `fields.ts` их нет: схема и сайт разошлись.

**Один json на тип, не по файлу на единицу.** Просили так. Цена известна и
записана в рисках.

## Расширяемость

Раскладка не зашита в репозиторий. Всё, что нужно для переезда поля между
файлами, — это значение `scope` в `fields.ts`:

- `image: "shared"` → `image: "translatable"`, и `loadEntry`/`saveEntity`
  начинают класть его в md. Больше нигде править не нужно: фронтенд работает с
  `Entry.shared.image` независимо от того, в каком файле значение лежит.
- Новое поле = одна строка в `fields.ts` плюс необязательная строка в плане
  `groups.ts`. Никаких правок в `saveEntry`.
- Новый тип контента = строка в `CONTENT_TYPES`, папка в `paths.ts`, схема.

Поэтому в репозитории не должно быть условий вида `if (field === "image")`.
Разложение — это чистая функция от `scope`, и она тестируется отдельно.

## Фаза 1. Схема — источник правды

1. `fields.ts`: заменить `only` и `shared` на одно поле
   `scope: "translatable" | "shared" | "local"`. Две несовместимые оси сейчас
   означают разное (`shared`+`only` у `path` — «правится один раз, пишется в
   RU»), и одна ось это убирает.
2. `frontmatter.json` оставить только translatable-полям: валидатор фронтматтера
   в редакторе не должен знать про json.
3. Shared и local описать в новом `content.schema.json`.
4. Переписать тест синхронизации схемы с `fields.ts` под разделение.

## Фаза 2. Файлы и ввод-вывод

5. `paths.ts`: `metaFile(type)`, `localFile(type)`,
   `unitFile(type, slug, lang)`.
6. Новый `json.ts`: чтение и запись json, стабильный порядок ключей, атомарная
   замена через temp-файл и rename. Каждый `saveEntry` переписывает json
   целиком, поэтому прерванная запись не должна оставлять обрезанный файл.
7. `.gitignore`: `src/content/*.local.json`.

## Фаза 3. Repository

Контракт, ради которого затевается переезд. Наружу только это, и одно и то же
для всех трёх типов:

```ts
loadEntry(type, slug): Entry | undefined;
saveEntry(type, slug, input: EntryInput): SaveResult;
listEntries(type): EntrySummary[];
createEntry(type, slug, input): Entry;
deleteEntry(type, slug): boolean;
renameEntry(type, slug, next): boolean;
```

8. Тип `Entry` — склеенный вид, который видит потребитель:
   `{ type, slug, shared, local, versions: Record<ContentLang, Version> }`, где
   `Version` — это `{ frontmatter, body }`. Фронтенд не знает, что translatable
   лежит в md, а shared в json.
9. `loadEntry`: читает json, local json и оба md, склеивает.
10. `saveEntry`: разбирает обратно — shared и local в json, translatable и body
    в md по языкам. Атомарно.
11. `listEntries`: источник — json, `langs` — по наличию md-файлов.
12. `renameEntry`: переименовать папку **и** ключ в json, атомарно.
13. Удалить `readUnit`, `writeUnit`, `createUnit`, `ensureUnit`, `summarize` —
    заменяются, а не живут рядом.

Имя `loadEntry`/`saveEntry`, а не `loadProject`/`saveProject`: то же самое для
всех типов, это и есть универсальность. `Project` в имени означало бы, что для
постов другой набор функций, а такого различия не будет.

## Фаза 4. Валидация

14. `validate.ts`: md проверять только по translatable-полям, json — по shared и
    local.
15. Новые проверки, главная из них — **в md не должно быть ни одного shared или
    local поля**, и наоборот. Это единственная защита от тихого возврата к
    старой модели, когда кто-то добавит `date` в frontmatter.
16. Проверка «ключ в json совпадает с именем папки» и «папка есть в json».

## Фаза 5. Старый контент

Контента нет, старый удалён целиком, миграции не было. Единственная
существовавшая единица — `easy-png-tools` — снесена вместе с `src/content`.

Из этого следует: обратной совместимости нет и не планируется, а фаза 4
закрывается без единой ошибки.

## Фаза 6. Редактор

18. `packages/editor/src/lib/api.ts` — единственное место с `fetch` на фронте.
    Закрывает проблему из оценки: URL в одной точке, ошибки в одном формате,
    типы не разъезжаются.
19. API: единый набор `/api/entries/...` на все типы вместо
    `/api/units/[type]/...`.
20. `UnitForm.svelte` работает с `Entry`, а не с двумя `UnitVersion`. Группы
    полей строятся из `scope`, ручной план `groups.ts` уходит: блок «общие» и
    блок «переводимые» получатся сами.
21. `+page.svelte`, `+layout.ts`, `[type]/[slug]/+page.ts` — на новый API.

## Фаза 7. Сайт

22. Первым шагом проверить, что Vite отдаёт json из `import.meta.glob` как
    модули с дефолтным экспортом. Если нет — весь план 7 меняется, и лучше
    узнать это до остального.
23. `content.ts`, `loaders.ts`: md по-прежнему через glob (только translatable),
    shared — из json.
24. `projects.ts`, `posts.ts`, `articles.ts`, `weekly.ts`: склейка md и json в
    `Project`, `Post`, `Article`. `date`, `tags`, `draft`, `order`, `status`,
    `repo`, `homepage`, `image` теперь из json.
25. Пройти все места в `src/routes/**`, где эти поля читаются.
26. `scripts/gen-mocks.ts`: генерировать json для моков тоже, иначе glob моков
    не найдёт пару.
27. `projects.test.ts`, `page.svelte.test.ts` — поправить.

## Фаза 8. Тесты и документация

28. Repository: round-trip save → load, инварианты разделения, rename, delete,
    отсутствующий файл. Отдельно — тест на то, что смена `scope` у поля меняет

29. `AGENTS.md`, `writing.md`, `plan-weekly.md` — новая модель. В `AGENTS.md`

## Риски

- **Один json на тип.** Любая правка переписывает файл целиком, в git будут
  конфликты при параллельной работе над двумя проектами. Пофайловый `index.json`
  в каждой папке дал бы мелкие диффы. Осознанно выбрано общим файлом.
- **`import.meta.glob` по json** — риск снят проверкой: совпадение есть, файл
  импортируется дефолтным экспортом, а отсутствующий файл даёт пустой объект и
  не роняет сборку.
- **Схема и сайт уже разошлись** (`icon`, `color`, `synced_at`). Поля добавлены
  в `content.schema.json` в фазе 1.
- **Обратный порядок.** Если фронтенд и сайт переведены на `Entry` раньше, чем
  репозиторий начнёт писать в json, старая раскладка развалится без всякой
  ошибки — просто перестанет читаться. Поэтому фазы шли строго по номеру.

## Порядок

Фазы строго по номеру. Смысл порядка: схема и репозиторий первыми, и только
потом потребители. Обратный порядок не сломал бы код на этапе записи, но оставил
бы окно, в котором сайт читает старое, а редактор пишет новое.

## Что вышло

### Отличия от плана

- **Миграции не было.** План предполагал `scripts/migrate-content.ts` для
  `easy-png-tools`. Контента нет, старый удалён целиком.
- **`groups.ts` остался** с ручным планом порядка и заголовков блоков. План
  обещал, что он уйдёт: блоки действительно строятся по `scope`, но заголовки и
  порядок внутри типа схемой не задаются. Убрать его — значит потерять «Темы»,
  «Порядок и статус» и подобное.
- **`lib/api.ts` не появился.** Fetch остался в компонентах. Единственное место
  с `fetch` на фронте не далось вычленить без цены: компонентов пять, а
  прослойка означала бы прокидывать типизированные ответы через generic-обвязку.
- **Проверка «папка есть в json» уехала из набора.** Общее поле может
  отсутствовать у единицы целиком, и тогда записи в json нет — это законное
  состояние. Проверяется обратное: запись в json без папки.
- **`validateEntry(type, slug)` не проверяет весь тип.** Редактор зовёт её на
  каждое сохранение, гонять весь тип дорого. Расхождение «запись без папки»
  видит только `lint:content`.

### Баги, найденные по дороге

- **`splitEntry` размазывал переводимое поле на оба языка.**
  `needs_translation`, правдивый только у EN, попадал в `index.ru.md`. Причина:
  baseline для переводимого собирался из карты, куда предварительно попадали
  значения _из_ языковых frontmatter. Починка: baseline строится только из
  `shared` и `local`, а спасательное правило для забытых полей осталось работать
  через отдельную карту.
- **Сообщение валидатора называло `postss.json`.** Имя файла собиралось из имени
  папки по правилу «папка + s». Теперь берётся из настоящего пути.
- **Сообщение об общем поле в frontmatter дублировалось** следом «unknown
  field». Добавлен `skip`: сказано один раз.
- **`validateUnit` получал имя папки вместо типа схемы**, из-за чего
  `metaFile("posts")` падал — ждал `post`.
- **На фронте `import.meta.glob` по конкретному json попал в `mergeShared`
  целиком**, а не значением: путь принимался за slug, и общие поля молча
  исчезали. Появилась `sharedFrom`, разворачивающая карту в запись.
- **`gen-mocks` писал старую раскладку своей сериализацией.** Поменян на
  `splitEntry` + `serializeUnit` из content-core: правило раскладки теперь одно
  на репозиторий и генератор.

### Проверка, которая ничего не проверяла

Сайт собран с `ssr = false`, тело рендерится в браузере, поэтому собранный HTML
пустой и не содержит контента. Проверять «доехали ли дата и теги» по артефактам
сборки бессмысленно — так и вышло, что два «успешных» осмотра страницы лгали.
Правильная проверка — тест, импортирующий настоящий модуль с его настоящим
`import.meta.glob`: `src/lib/loaders.test.ts`.
