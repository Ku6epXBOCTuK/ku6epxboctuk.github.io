# План: генерация weekly

Отчёты генерируются автоматически из git-логов, руками не создаются. Редактор
weekly не правит — типа нет в `CONTENT_TYPES` и в `fields.ts`.

Вынесено из `plan-automation.md` §5. Остальные разделы того файла описывали CLI
`c:new`, которого больше нет: проекты заводятся через редактор.

## Источник проектов

Только frontmatter в `src/content/projects/*/index.ru.md`. Отдельного манифеста
нет: `projects.yaml` пробовали, это второе место с теми же данными и оно
разъезжается с контентом.

Список проектов с уже разрешёнными папками даёт `content-core`:

```ts
import { checkProjectPaths } from "@ku6epxboctuk/content-core";

// slug, title, declared, resolved, state: ok | not-set | missing | not-a-repo
const reports = checkProjectPaths();
```

Путь лежит в поле `path` проекта, **относительно корня сайта**: `../brul`. В git
попадает `../brul`, а не `C:\Users\...` — структура диска не утекает. Поле
необязательное и редактируется только в RU-версии: это факт о машине, а не о
переводе. Абсолютные пути тоже понимаются, но в репозиторий утекает раскладка
диска, поэтому форма подсказывает относительные.

Что из этого следует:

- путь не задан → проект просто не участвует в weekly, **это не ошибка**;
- путь есть, папки нет или это не git-репозиторий → проект в отчёт не идёт, а
  проблема появляется на странице `/errors` в редакторе;
- имя папки может не совпадать с именем репо (`now_playing` лежит в
  `streaming/`), сверять по имени нельзя — сверяем наличие `.git`;
- `slug` и `title` переопределять нечего, они уже в frontmatter;
- `frozen` из старого манифеста заменён витринным `status` (`raw` / `ready` /
  `need_review`), пропускать можно по `status: raw`.

## Алгоритм

1. Собирает список проектов из `src/content/projects/*/index.ru.md`.
2. Период — предыдущая неделя (понедельник–воскресенье): команда запускается в
   начале следующей недели. Явно: `--week 2026-W36`.
3. Для каждого проекта:
   - `path` не задан → пропуск молча, не ошибка;
   - `path` есть, но `state` не `ok` → проект пропускается, проблема уже видна
     на `/errors` в редакторе;
   - `git log --since --until` — коммиты за период;
   - фильтрует шум: merge-коммиты, `[skip ci]`, bump/version-коммиты;
   - группирует по conventional-commits типам: feat / fix / docs / refactor /
     chore / прочее (префиксы уже нормализованы);
   - читает `CHANGELOG.md`, если есть, — записи за период;
   - считает статистику: коммиты, файлы, +/− строки (числа — для `excerpt`).
4. Собирает отчёт из блоков по проектам, где была активность.
5. Пишет пару в `src/content/weekly/<понедельник-отчётной-недели>/` (ISO
   `YYYY-MM-DD`): `index.ru.md` — основной язык, `index.en.md` — копия-заглушка
   с `needs_translation: true`. Body — человекочитаемый лог по проектам.
   `excerpt` — короткая сводка (проекты, коммиты, главное) для соцсетей.
6. Печатает сводку: проектов с активностью, коммитов, файл создан/обновлён,
   список пропущенных из-за недоступной папки.

## Вид файла

`src/content/weekly/2026-09-07/index.ru.md`:

```markdown
---
title: weekly 2026-W37
date: 2026-09-07
excerpt: 4 проекта, 23 коммита. now-playing: v1.2, git-overhooks: новый hooks api.
draft: true
---

## now-playing

- feat(overlay): blur behind panel
- fix(timer): timezone drift on resume

## git-overhooks

- feat: hooks api v2
- docs: readme examples

## итого

23 коммита в 4 проектах.
```

`draft: true` проставляется всегда: перед пушем человек вычитывает текст и
снимает флаг, как у любого черновика.

## Режимы

- `npm run gen:weekly` — предыдущая неделя, запись файла.
- `--week 2026-W36` — конкретная неделя (догенерировать пропущенное).
- `--check` — только отчёт в консоль, без записи.
- повторный запуск за ту же неделю → файл перезаписывается целиком (источник
  правды — git, а не файл).

## Архитектура под AI

Скрипт разделён на две фазы с явной границей:

- **Сбор** (детерминированная): git-логи → структура `WeeklyData` (проекты,
  коммиты по типам, статистика). Отладка: вывод в консоль/JSON.
- **Рендер** (заменяемая): `WeeklyData` → markdown-отчёт по шаблону. Позже —
  нейронка: тот же `WeeklyData` → промпт → связный текст и `excerpt`. Подмена
  рендера не требует переписывания сбора.

## Гарантии

- не ходит в сеть: только локальные git-команды и файлы;
- проекты без активности за период не попадают в отчёт;
- повторный запуск безопасен.

## Что предстоит решить

- **фильтр по `status: raw`** — пока неочевидно, значит ли `raw` «проект не
  ведётся». В старом манифесте это делал `frozen`.
- **содержательный перевод weekly** и AI-рендер вместо шаблона — этап 2.
- **scheduled GitHub Actions** для еженедельного запуска — этап 2. Смысла мало,
  пока скрипт ходит в локальные клоны: на раннере нужен `actions/checkout`
  каждого репозитория.
