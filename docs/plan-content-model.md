# Модель контента и процесс создания

> Статус: на ревью. Один из трёх планов: дизайн, модель контента, автоматизация.
> Этот — базовый: определяет типы контента, схемы frontmatter и процесс работы с
> ручным контентом. Старт с нуля без миграций (старые статьи чисто текстовые —
> при желании просто копируются руками). Контент живёт в `src/content/*`, каждая
> единица — папка с `index.<lang>.md`, тизер и `readingTime` берутся из
> raw-тела.

## Решено по итогам ревью

Открытые вопросы из прошлой версии закрыты:

1. **`/posts`** — отдельная страница; на главной блок «последние посты», причём
   **количество настраивается** (конфиг `HOME_RECENT_POSTS`, дефолт 3) — см.
   план дизайна.
2. **`type` у проектов убирается.** Остаются `subtitle` (короткое описание) и
   свободный массив `tags` — старый enum не тащим, новые категории задаются
   тегами на лету.
3. **Черновики:** в dev видны с бейджем «draft», в production скрыты; в
   автопостинг не попадают.
4. **Переводы:** в соцсети уходит только основной язык, перевод не постится
   никогда. `index.en.md` создаётся автоматически вместе с основной версией
   (копия с `needs_translation: true`). Непереведённые статьи ничего не ломают.
5. **Чип-переключатель ru/en** — интерфейс планируем и делаем сейчас, контент
   переводов — по мере готовности.

## Решения по вопросам из беклога

Открытые вопросы перенесены из `docs/backlog.md`, закрыты:

1. **Структура файлов: папка на каждую единицу.** Каждый элемент контента — своя
   папка со всеми языками внутри: `src/content/<type>/<slug>/index.ru.md` +
   `index.en.md`. Slug — это имя папки, уникальность обеспечена по построению
   (не нужен slug с датой; для weekly slug берётся из даты — «просто дата»).
   Картинки и вложения лежат рядом в папке элемента.
2. **Тизер и `readingTime` — из raw-тела, не из frontmatter.** Тип разработки
   решён: raw-маркдаун подтягивается параллельным `import.meta.glob` с
   `query: "?raw"` (стандартная фича Vite, без зависимости от API
   `vite-plugin-svelte-md`), тизер — обрезка по `<!--more-->`, `readingTime` —
   слова/200 из тела. Поле excerpt/teaser во frontmatter не вводим, дублирования
   нет.
3. **Двуязычность — для всех типов контента.** Статьи и посты — сейчас; проекты
   и weekly — позже, когда генераторы научатся. `index.en.md` создаётся сразу
   вместе с основной версией — автоматическая копия с `needs_translation: true`
   (см. «Двуязычность»).

## Цель

Перейти к четырём типам контента с разной степенью автоматизации. Сайт
перезапускается с нуля: старые форматы (`tag` строкой, `apr 2026`, excerpt) не
поддерживаются, но специального миграционного процесса нет — старые статьи чисто
текстовые, любую можно просто скопировать в новую папку (см. «Перенос старых
статей»).

Каждая единица любого типа живёт в своей папке:

```txt
src/content/
  articles/<slug>/index.ru.md   # или index.en.md
  posts/<slug>/index.ru.md
  projects/<slug>/index.ru.md
  weekly/<дата-понедельника>/index.ru.md
```

| Тип        | Что это                                      | Как создаётся       |
| ---------- | -------------------------------------------- | ------------------- |
| `posts`    | короткие посты (формат твиттер/телеграм)     | вручную, визард     |
| `articles` | большие статьи с картинками и кодом          | вручную, визард     |
| `projects` | описание проектов: картинка, исходники, демо | скрипт из README    |
| `weekly`   | автогенерируемые отчёты о недельной работе   | скрипт из git-логов |

Руками создаются только посты и статьи. Проекты и weekly — автоматические
(скрипты описаны в плане автоматизации); здесь фиксируются только их схемы.

## Типы контента

### 1. `posts` — короткие посты

Формат твиттер/телеграм: небольшой текст, опционально картинка и/или ссылка.
Папка: `src/content/posts/<slug>/`, файлы `index.ru.md` + `index.en.md` (перевод
— автоматическая копия, см. «Двуязычность»).

```yaml
---
title: короткий заголовок
date: 2026-09-08
tags:
  - svelte
image: images/2026-09-08.jpg # опционально, путь относительно папки поста
link: https://example.com # опционально, внешняя ссылка
draft: true
---
текст поста. небольшой. без структуры заголовков.
```

- body и есть контент — целиком уходит и на сайт, и в соцсети (без
  `<!--more-->`, в отличие от статей);
- `image` — картинка к посту (для сайта и для соцсетей);
- `link` — если пост «про что-то снаружи» (релиз, чужая статья).

### 2. `articles` — большие статьи

Полноценные статьи с картинками, кодом, таблицами. Обязательна короткая версия,
показываемая «до полного открытия». Папка: `src/content/articles/<slug>/`
(создаётся визардом).

```yaml
---
title: The Entity Component System
date: 2026-04-15
tags:
  - engineering
  - gamedev
image: images/ecs-cover.jpg # опциональная обложка, относительно папки статьи
draft: true
---
вступление — короткая версия статьи.

<!--more-->

полный текст статьи: разделы, картинки, код, таблицы...
```

- единый источник короткой версии — маркер `<!--more-->` в body (отдельное поле
  excerpt/teaser не вводим — убираем дублирование);
- список статей и превью показывают текст до `<!--more-->` + блок «читать
  дальше»;
- `prepare-post.ts` уже умеет резать по `<!--more-->` — переиспользуется;
- тизер и `readingTime` для сайта считаются из raw-тела на этапе сборки (см.
  «Решения по вопросам из беклога», п. 2);
- языки и суффиксы `index.*.md` — см. раздел «Двуязычность».

### 3. `projects` — проекты

Описание проекта: картинка, ссылка на исходники, ссылка на живой проект (если
есть). Папка: `src/content/projects/<slug>/`, файл `index.ru.md` (создаётся
скриптом синхронизации из манифеста).

```yaml
---
title: now-playing
subtitle: obs browser source
description:
  obs browser source widget that displays the currently playing track.
tags:
  - html
image: images/now-playing.jpg # относительно папки проекта
repo: https://github.com/Ku6epXBOCTuK/now_playing # исходники
demo: https://ku6epxboctuk.github.io/now_playing # живой проект, опционально
icon: ✦ # эмодзи/символ для иконки проекта, опционально (по умолчанию ✦)
color: periwinkle # акцент иконки: coral / periwinkle / sky (по умолчанию coral)
status: ready
synced_at: 2026-09-08
draft: false
---
```

- `url` переименовывается в `repo`, добавляется `demo` (может отсутствовать);
- `status`, `synced_at`, `description` обслуживаются скриптом синхронизации из
  README (план автоматизации), остальное — вручную.
- `icon` — эмодзи/символ в квадратной иконке проекта (по умолчанию `✦`); `color`
  — акцент иконки: `coral` / `periwinkle` / `sky` (по умолчанию `coral`).
  Приходят из `projects.yaml` (план автоматизации), показываются на карточке
  проекта и в hero.

### 4. `weekly` — автоматические отчёты

Недельные отчёты о работе. Генерируются скриптом из git-истории проектов,
вручную не создаются вообще. Папка: `src/content/weekly/<дата-понедельника>/`,
файл `index.ru.md` (slug = ISO-дата понедельника недели).

```yaml
---
title: weekly 2026-W37
date: 2026-09-07 # понедельник недели
excerpt: 4 проекта, 23 коммита. now-playing: v1.2, git-overhooks: hooks api.
generated: true
generated_at: 2026-09-08T10:00:00Z
---
```

- `generated: true` — явная пометка автогенерации (для UI и линтера);
- генерация, формат body и запуски — в плане автоматизации.

## Сквозные решения

- **Даты — ISO `YYYY-MM-DD` везде.** Старый формат `apr 2026` не сортируется и
  блокирует weekly-автоматику. Человекочитаемый вид (`apr 2026`) формирует UI.
- **`tags` — всегда массив.** Поле `tag` (строка, разделённая пробелами)
  удаляется. Единообразно для всех типов.
- **`draft: true|false` — у всех типов.** В production-сборке черновики не
  попадают на сайт и в автопостинг; в dev — видны (предпросмотр) с бейджем
  «draft» в углу карточки.
- **Язык — из имени файла.** `index.ru.md` / `index.en.md`; поле `lang` во
  frontmatter не нужно (убираем источник рассинхрона).
- **Сортировка списков по дате, свежие сверху** (`src/lib/*`).

## Двуязычность контента

Требование: каждая единица контента может существовать на двух языках (русский +
английский), причём не у всех будет перевод. Решение работает и для ручного
письма, и для автопостинга, и не требует переделки потом.

Структура — папка на единицу, язык в имени файла:

```txt
src/content/articles/
  ecs-deep-dive/
    index.ru.md        # основная версия
    index.en.md        # перевод
src/content/posts/
  my-thought/
    index.ru.md
    index.en.md        # авто-копия с needs_translation
```

- у любой ручной единицы (пост/статья) оба файла есть сразу: `index.ru.md` —
  основная версия, `index.en.md` — автоматическая копия;
- пара связывается папкой (общий slug = имя папки), язык — суффиксом имени
  файла;
- **Создание перевода — автоматическое.** Визард при создании поста/статьи сразу
  пишет оба файла: `index.ru.md` для редактирования и `index.en.md` — копию с
  `needs_translation: true` во frontmatter и подписью-заглушкой в теле.
  Отдельного процесса «создать файл перевода» нет. Перевёл — снял флаг
  (`needs_translation: false`, поле видно во Frontmatter CMS и проверяется
  линтером);
- пока `needs_translation` — на сайте en-версия показывает заглушку с плашкой
  «перевод готовится», в списках карточка остаётся одна;
- в списке любой единицы всегда одна карточка; смена языка контента — кнопка
  «read in english» / «читать на русском» на детальной странице (интерфейс — в
  объёме сейчас, контент переводов — по мере готовности);
- URL версий — префикс локали: `/ru/articles/<slug>` и `/en/articles/<slug>`
  (см. «Локализация сайта (i18n)»).
- автопостинг: в соцсети уходит только версия основного языка (ru), перевод —
  никогда, включая `needs_translation`;
- проекты и weekly: пока только `index.ru.md`; переводы появятся на этапе 2,
  когда генераторы их научатся создавать.

## Локализация сайта (i18n)

Решение: полный префикс локали — каждый маршрут живёт под `/ru/…` или `/en/…`
(`ru` — дефолтная локаль). Сравнение вариантов:

- **префикс `/ru/…` `/en/…` (выбран)** — единый признак языка у любого URL
  (список, детальная, страницы, главная): язык виден до остального пути;
  стандарт для статических сайтов (Next.js, Astro, Paraglide), дешёвые
  sitemap/редиректы;
- `/posts/<slug>/ru` — ломает иерархию (у `/posts` нет языка), не расширяется на
  страницы типа about, язык «прячется» в конце;
- «ru без префикса + только `/en/`» — рабочий, но несимметричный: у корня нет
  канонического вида, переключатель ведёт на разные правила;
- `.en`-суффикс (как раньше) — ручной парсинг `/(.+).(ru|en)$/`, некрасивые URL,
  не совместим с единым префиксом.

Маршруты: `src/routes/[lang]/…`, где `[lang]` ∈ `ru|en`. Списки/детальные
перебирают оба языка в `entries()` (`{lang, slug}`).

Старые URL без префикса — редирект 302 на дефолтную локаль: `/`, `/posts/…`,
`/articles/<slug>` → `/ru/…`; старый `.en`-суффикс `/articles/<slug>.en` →
`/en/articles/<slug>`. Для GitHub Pages пререндер-редиректы SvelteKit собирает в
HTML с meta-refresh.

UI-строки сайта (навигация, hero, секции, футер, плашки, кнопки, доступные
подписи) — словарь `src/lib/i18n.ts` (`{ ru, en }`), текущий язык =
`$page.params.lang`. Язык контента совпадает с языком сайта: `/en/posts/x` даёт
en-интерфейс и en-контент (или ru-контент с плашкой «перевод готовится», если
перевода нет).

Автопостинг (`scripts/templates.json`) — URL ссылаются на дефолтную локаль с
префиксом (`https://…/ru/articles/{slug}`), без редиректа.

Проекты и weekly пока присутствуют только на `index.ru.md` — на `/en/` они
показываются как есть, контент на основном языке (тот же принцип, что и при
`needs_translation`). Переводы проектов/weekly — фаза automation.

Почему папка, а не плоские файлы (`slug.md` + `slug.en.md`): уникальность slug
по построению, картинки и вложения живут рядом с контентом, пара языков видна в
одной папке, списки в lib-хелперах и схемы frontmatter едины для всех типов.

## Процесс создания ручного контента (визард)

Проблема: чтобы написать пост/статью, нужно зайти в папку, создать файл среди
других, вручную набрать frontmatter, не забыть `<!--more-->` для статьи.
Решение: CLI-визард `scripts/new-content.ts` (tsx, без новых зависимостей).

```bash
npm run new                        # интерактивный визард
npm run new post my-thought        # быстрый режим: пост
npm run new article ecs-deep-dive  # статья с шаблоном и <!--more-->
```

Поведение:

1. **Тип**: post / article (projects и weekly визард не создаёт — у них свои
   автоматические процессы).
2. **Slug**: валидация на лету (`a-z0-9`, `-`), проверка что папка не
   существует. Создаётся папка `src/content/<type>/<slug>/` сразу с обоими
   файлами: `index.ru.md` (основная версия) и `index.en.md` — копия с
   `needs_translation: true`. Отдельного шага «создать перевод» нет.
3. **Вопросы по типу** (все с дефолтами, Enter — принять): post — теги, link,
   image; article — теги; общие — title (дефолт из slug).
4. **Создание файлов** по шаблону типа: оба файла (`index.ru.md` +
   `index.en.md`), дата — сегодня (ISO), у статьи в обоих сразу вставлен
   `<!--more-->` с подписью-подсказкой, что выше тизера. Копия-перевод
   (`index.en.md`) получает `needs_translation: true`. Это снимает главный
   источник ошибок автопостинга.
5. Сообщение «файл создан: <путь>» — дальше редактор и Frontmatter CMS
   (обновлённые схемы дают там те же поля; CMS остаётся вторым путём создания).

Черновик живёт рядом с контентом (`draft: true` в самом файле) — никаких
отдельных папок черновиков, путь публикации не меняется.

## Старт с нуля и перенос старых статей

Папки контента стартуют пустыми:

- `src/content/posts/`, `src/content/projects/`, `src/content/weekly/` — очищены
  от старых файлов (в weekly оставлен `.gitkeep`);
- `src/content/articles/` — пустая;
- наполняем сразу по новым схемам: первый пост/статья создаются визардом,
  проекты — через `sync:projects` после заполнения `projects.yaml`.

Старые статьи чисто текстовые, поэтому отдельный процесс переноса не нужен: если
какую-то захочется оставить на сайте, файл просто кладётся в
`src/content/articles/<slug>/`, и у него руками правится frontmatter под новую
схему (дата в ISO, `tag` → массив `tags`, при желании `<!--more-->` после
вступления) — пара минут на статью. Копия-перевод `index.en.md` для такой
единицы создаётся той же командой `npm run new article <slug> --sync` (или
вручную по шаблону); линтер предупреждает (warn), если у единицы нет
`index.en.md`. Никаких миграционных скриптов; решается по ходу, статья за
статьёй, а не все сразу.

Старые решения, которые не тащим дальше: `tag` строкой, `excerpt` во frontmatter
статей, даты `apr 2026`, поле `url` у проектов.

## Изменения в кодовой базе

- Контент переезжает в `src/content/*`: `src/content/articles/`,
  `src/content/posts/`, `src/content/projects/`, `src/content/weekly/` (уже
  сделано, чеклист п. 16–17).
- `src/lib/content.ts` → общий хелпер; паттерн глоба `…/index.{ru,en}.md`;
  параллельный raw-глоб (`query: "?raw"`) даёт тело.
- `src/lib/articles.ts` (пары ru/en по папкам, slug = имя папки, lang из имени
  файла), `lib/posts.ts`, `lib/projects.ts`, `lib/weekly.ts` — тип хелперов
  единый.
- Роуты под префиксом локали: `/ru/…` и `/en/…` — общий сегмент
  `src/routes/[lang]/…` вмещает главную, about, lists и детальные
  (articles/posts/projects/weekly); навигация берётся из словаря
  `src/lib/i18n.ts`. Старые пути (`/`, `/articles`, `/articles/<slug>`,
  `.en`-суффиксы) — редирект 302 на `/{lang}/…` с дефолтной локалью ru.
- `frontmatter.json` — новые схемы типов (post, article, project, weekly), без
  `Type` и без `lang`, с полем `needs_translation` (article/post); pageFolders
  под `src/content/articles`, `src/content/posts`.
- `scripts/lint-content.ts` — схемы под 4 типа: ISO-даты, массив tags,
  `<!--more-->` для статей, `generated: true` для weekly, `needs_translation`
  только в `index.en.md`, отсутствие `lang` во frontmatter; предупреждение (не
  ошибка), если у единицы нет `index.en.md`.
- `scripts/prepare-post.ts` — CONTENT_DIRS на `src/content/*` + тип article
  (тизер до `<!--more-->`); `scripts/templates.json` — url-шаблон
  `/articles/{slug}` и шаблоны для post и weekly.
- `.github/workflows/publish.yml` — триггер на `src/content/articles/**`,
  `src/content/posts/**` (+ уже имеющиеся `projects/**`, `weekly/**`).
- `scripts/new-content.ts` + npm-скрипт `new` — визард: сразу пара файлов
  `index.ru.md` + `index.en.md` (копия с `needs_translation: true`); `--sync`
  досоздаёт копию для уже существующей единицы.

и детальная страница проектов. Подробности — «Локализация сайта (i18n)» выше и
