## Текущее состояние

### CI/CD

- `deploy.yml` — push в main → build → GitHub Pages
- `publish.yml` — push в main → prepare → publish в TG/Discord

### Локальные скрипты

- `lint-content.ts` — валидация frontmatter
- `prepare-post.ts` / `publish.ts` — подготовка и отправка в соцсети
- `new-content.ts` — визард создания нового контента
- `check:all` — полная проверка (format, lint, check, test)

### 2. Локальный флоу

Подготовка и публикация — полностью локально. CI только собирает и деплоит.

### 3. Линтер контента — изменения

**Сейчас проверяет:** типы полей, форматы, обязательные поля, `<!--more-->` в
статьях, `isMock: true` у weekly (будет пересмотрено — см. 3c),
`needs_translation` только в `index.en.md`.

**Проблема:** запрещено только поле `lang` (захардкожено). Остальные лишние поле
линтер не видит.

#### 3a. Общая проверка неизвестных полей

Вместо хардкода `lang` — проверять ВСЕ поля frontmatter по схеме из
`frontmatter.json`. Любое поле, которого нет в схеме для данного типа контента —
**error**. Хардкод `lang` убирается, он уже покрыт общей проверкой.

Поле `isMock` — флаг mock-контента (см. 3d), добавлен во все четыре схемы.
Обычный weekly — обычный контент без служебных флагов: никаких
`generated`/`generated_at` в репо нет (вымещены, включая упоминания в планах).
Правило линтера «weekly должен иметь флаг автогенерации» — удалено.

#### 3b. Обязательная пара языковых файлов

Для каждого контента: если есть `index.ru.md` — должна быть `index.en.md`, и
наоборот. Не варн, а **error**. Сейчас линтер только варнит при отсутствии
`index.en.md`, но не проверяет обратное и не требует наличия обоих.

#### 3c. Проверка `draft`

Добавить warning при `draft: true`. Варн выводится для **всего** контента, кроме
mock-контента (флаг `isMock: true`).

**Согласованность пары:** `draft` в `index.ru.md` и `index.en.md` обязан
совпадать. Иначе — **error** (иначе на проде статья окажется в одном переводе:
`draft:false`-версия опубликуется, `draft:true`-версия обрежется).

#### 3d. `isMock` — флаг mock-контента

`isMock: true` — маркер mock-контента (тестовые файлы, созданные `gen-mocks.ts`
для проверки/разработки). **Всегда** с `draft: true` — mock без draft
невозможен, иначе он попадёт на прод. Линтер: `isMock: true` без `draft: true` —
**error**.

Линтер: если `isMock: true` — это mock → `draft`-варн не выводим, но сам факт
`draft: true` обязателен. `needs_translation` не проверяем.

**Weekly — как весь остальной контент.** Weekly создаётся скриптом, но не
является mock и не имеет поля `isMock`. Исключение: mock-weekly (созданные
`gen-mocks.ts`) имеют `isMock: true` и `draft: true` — это штатное состояние.
Правила для weekly те же, что для всего остального:

- `draft`-варн выводится для обоих файлов — `draft` надо снять с каждого после
  проверки;
- en-версия weekly имеет `needs_translation: true` — линтер это видит и
  пропускает (это штатное состояние, не ошибка).
