# Как добавить контент

Через редактор. Он локальный: пишет файлы в `src/content` на этом же диске.

```bash
pnpm editor
```

В консоли появится ссылка `http://127.0.0.1:4321/` — открой её. Авторизации нет,
редактор слушает только loopback. Дальше коммит руками, деплой сам.

## Что где лежит

```txt
src/content/posts/<slug>/index.ru.md      # пишем здесь
src/content/posts/<slug>/index.en.md      # перевод
```

Тип определяет папку: `posts/`, `articles/`, `projects/`. `weekly` редактор не
трогает — отчёты генерируются автоматически.

## Порядок работы

1. На списке выбери тип, впиши slug, нажми «создать» — откроется форма.
2. Заполни поля на вкладке **RU**, впиши текст.
3. Нажми «сохранить RU».
4. Перейди на вкладку **EN** и нажми «Скопировать из RU» — появится
   `index.en.md` с пометкой `needs_translation` и заглушкой вместо текста.
5. Когда переведёшь — замени текст и убери `needs_translation`.
6. «сохранить обе» пишет обе версии разом.
7. `git commit` → `git push`.

## Поля

Общие для всех типов: `title` (обязательное), `date` (ISO `YYYY-MM-DD`), `tags`
через запятую, `image` (обложка), `draft`.

| Тип     | Особое                                                                    |
| ------- | ------------------------------------------------------------------------- |
| post    | `link` — внешняя ссылка                                                   |
| article | `<!--more-->` в тексте обязателен, кнопка вставляет сама                  |
| project | `repo` и `description` обязательны, `homepage`, `status`, `order`, `path` |

`order` у проектов — число: меньше значит выше на странице. Без него порядок
задаётся только вручную.

`draft: true` — в production не попадает на сайт, в `pnpm dev` виден с бейджем.
Сними флаг перед пушем.

## Локальная папка проекта

У проекта есть поле **«Локальная папка»** (`path`) — путь к клону репозитория на
этом диске. Он нужен генератору weekly, чтобы собрать git-логи за неделю.

Пиши относительно корня сайта:

| проект             | значение                               |
| ------------------ | -------------------------------------- |
| brul               | `../brul`                              |
| twitch-ext         | `../twitch-ext`                        |
| effect-ts-practice | `../../open_source/effect-ts-practice` |

Абсолютный путь тоже работает, но в git уедет вся раскладка диска, поэтому
относительный лучше. Поле необязательное и видно только на вкладке **RU**: это
факт о машине, а не о переводе, в `index.en.md` оно не попадает.

Клона нет или проект не нужен в weekly — оставь пустым, это не ошибка.

## Страница ошибок

Ссылка **ошибки** в шапке редактора. Показывает проекты, которые weekly не
сможет обойти: папка из `path` не нашлась или оказалась не git-репозиторием.
Здесь же — список проектов без `path` (они просто не участвуют) и кнопка
«перепроверить».

## Перевод

Язык определяется именем файла, поля `lang` в frontmatter нет и линтером
запрещено. Пока `index.en.md` содержит `needs_translation: true`, английская
версия показывает заглушку «перевод в работе». Если английский не нужен — удали
`index.en.md` через кнопку удаления, сайт покажет русскую.

`draft` должен совпадать в паре файлов.

## Картинки

Drag-drop в обложку или в текст.

- обложка приводится ровно к 1200×630 и обрезается по центру
- картинка в тексте — ширина до 1200, высота по пропорции, мелкие не раздуваются
- всё сохраняется в webp; GIF остаётся GIF, чтобы не потерять анимацию
- SVG не принимается
- в текст вставляется абсолютный путь: `![alt](/images/x.webp)`. Относительные
  пути в markdown не работают, `vite-plugin-svelte-md` их не переписывает

## Панель замечаний

После каждого сохранения показывается результат `pnpm lint:content` для этой
единицы: ошибки красным, предупреждения жёлтым. Сохранение не блокируется —
можно дописывать постепенно, замечания догонят на следующем сохве.

## Проверка

```bash
npm run lint:content   # только валидация frontmatter
pnpm verify            # format → check → lint → тесты
```

`pnpm lint:content` отдельно прогоняет `tsx scripts/lint-content.ts`, который
теперь тонкая обёртка над `content-core` — правила одни и те же, что видит
редактор.

## Доступ из сети

Редактор не имеет авторизации и слушает только `127.0.0.1`: из интернета и из
другой машины он недоступен. Страница в браузере может отправить запрос на
localhost — это значит, что доверять Origins и `Sec-Fetch-Site` не нужно, а
защиты от скриптов чужой страницы нет.

## Устройство экрана

Тёмная тема, свои токены в `packages/editor/src/lib/theme.css`. Тема сайта к
редактору отношения не имеет — он не импортирует `src/app.css` и не должен
перекрашиваться вместе с сайтом.

Форма двухколоночная: поля слева, markdown справа и прилипает при прокрутке. На
узком экране колонки складываются в одну. Ссылка «редактор» в хедере ведёт на
главную, у ссылки «ошибки» горит красная точка, когда weekly не сможет обойти
какой-то проект.
