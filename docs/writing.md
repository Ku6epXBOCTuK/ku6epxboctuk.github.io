# Как добавить контент

> **Это отладочная версия документа, а не руководство для человека.** Здесь
> описано, где что лежит на диске и что значат поля, — это нужно, пока идёт
> работа над моделью хранения. По назначению здесь должно быть описание
> интерфейса редактора: блоки, стрелки, статусы, куда нажимать. Переписать — в
> [docs/backlog.md](backlog.md), первым пунктом.

Через редактор. Он локальный: пишет файлы в `src/content` на этом же диске.

```bash
pnpm editor
```

В консоли появится ссылка `http://127.0.0.1:4321/` — открой её. Авторизации нет,
редактор слушает только loopback. Дальше коммит руками, деплой сам.

## Что где лежит

```txt
src/content/posts/<slug>/index.ru.md      # переводимое: заголовок, текст
src/content/posts/<slug>/index.en.md      # перевод того же
src/content/posts.json                    # общее на тип: дата, теги, обложка, draft
src/content/projects.local.json           # локальное: путь к клону (в гитигноре)
```

Тип определяет папку: `posts/`, `articles/`, `projects/`. `weekly` редактор не
трогает — отчёты генерируются автоматически.

Правило одно: **что переводится — в `index.<lang>.md`, что не переводится — в
`<type>s.json`, что является фактом о машине — в `<type>s.local.json`.** Куда
именно уходит поле, решает `scope` в `packages/content-core/src/fields.ts`.
Форма знает только это правило и не знает имён файлов.

## Порядок работы

1. На списке выбери тип, впиши slug, нажми «создать» — откроется форма.
2. Заполни блок **«Общее»** — он один для обоих языков.
3. Заполни переводимые поля: RU слева, EN справа. Стрелки между колонками
   копируют поле из одного языка в другой.
4. Текст — внизу, тоже RU и EN рядом. «RU → EN» копирует текст, пока EN пуст.
5. Нажми **«сохранить»**. Одна кнопка на единицу: обе языковые версии и все json
   пишутся одним запросом, разойтись на диске им негде.
6. `git commit` → `git push`.

## Поля

Общие для всех типов: `title` (обязательное, переводимое), `date` (ISO
`YYYY-MM-DD`), `tags` через запятую, `image` (обложка), `draft`.

| Тип     | Особое                                                                    |
| ------- | ------------------------------------------------------------------------- |
| post    | `link` — внешняя ссылка                                                   |
| article | `<!--more-->` в тексте обязателен, кнопка вставляет сама                  |
| project | `repo` и `description` обязательны, `homepage`, `status`, `order`, `path` |

`order` у проектов — число: меньше значит выше на странице. Без него порядок
задаётся только вручную.

`draft: true` — в production не попадает на сайт, в `pnpm dev` виден с бейджем.
Сними флаг перед пушем. Флаг один на единицу и лежит в json, поэтому расходиться
между языками он не может.

## Локальная папка проекта

У проекта есть поле **«Локальная папка»** (`path`) — путь к клону репозитория на
этом диске. Он нужен генератору weekly, чтобы собрать git-логи за неделю.

Пиши относительно корня сайта:

| проект       | значение                        |
| ------------ | ------------------------------- |
| example-repo | `../example-repo`               |
| example-cli  | `../example-cli`                |
| example-lab  | `../../open_source/example-lab` |

Оно лежит в `projects.local.json`, а этот файл в гитигноре — **абсолютный путь
тоже можно**, в git он не попадёт. Значение нужно только на этой машине, поэтому
и редактируется один раз, а не на каждый язык.

Клона нет или проект не нужен в weekly — оставь пустым, это не ошибка.

## Перевод

Язык определяется именем файла, поля `lang` в frontmatter нет и линтером
запрещено. `index.en.md` создаётся вместе с `index.ru.md` и не удаляется
отдельно — пока в нём `needs_translation: true`, английская версия показывает
заглушку «перевод в работе».

Флага `needs_translation` в RU не бывает: он правдив только у EN, и лежит он в
`index.en.md`, а не в общем json. Стрелка `→` рядом с полем копирует значение из
RU в EN.

Если английский не нужен — оставь `needs_translation` включённым или удали
единицу и заведи заново без EN. Форма переводимые поля показывает парами, а не
вкладками.

## Картинки

Drag-drop в обложку или в текст.

- обложка приводится ровно к 1200×630 и обрезается по центру
- картинка в тексте — ширина до 1200, высота по пропорции, мелкие не раздуваются
- всё сохраняется в webp; GIF остаётся GIF, чтобы не потерять анимацию
- SVG не принимается
- в текст вставляется абсолютный путь: `![alt](/images/x.webp)`. Относительные
  пути в markdown не работают, `vite-plugin-svelte-md` их не переписывает

Обложка одна на оба языка: `image` — общее поле. Если понадобится своя картинка
для перевода, меняется одна строка `scope` в `fields.ts`, а не редактор.

## Панель замечаний

После каждого сохранения показывается результат `pnpm lint:content` для этой
единицы: ошибки красным, предупреждения жёлтым. Сохранение не блокируется —
можно дописывать постепенно, замечания догонят на следующем сохранении.

Валидатор проверяет и языковые файлы, и json. Самое частое замечание сейчас —
общее поле в frontmatter:

```txt
index.ru.md: field "repo" is not translatable — belongs in projects.json, not in frontmatter
```

Это единственная защита от возврата к старой раскладке, когда всё снова
складывается в md.

## Проверка

```bash
npm run lint:content   # валидация контента: md и json
pnpm verify            # format → check → lint → тесты
```

`pnpm lint:content` отдельно прогоняет `tsx scripts/lint-content.ts`, который
тонкая обёртка над `content-core` — правила одни и те же, что видит редактор.

## Доступ из сети

Редактор не имеет авторизации и слушает только `127.0.0.1`: из интернета и из
другой машины он недоступен. Страница в браузере может отправить запрос на
localhost — это значит, что доверять Origins и `Sec-Fetch-Site` не нужно, а
защиты от скриптов чужой страницы нет.

## Устройство экрана

Тёмная тема, свои токены в `packages/editor/src/lib/theme.css`. Тема сайта к
редактору отношения не имеет — он не импортирует `src/app.css` и не должен
перекрашиваться вместе с сайтом.

Форма построена строками, а не колонками: каждый ряд — RU слева, EN справа, а
между ними узкая колонка со стрелками копирования. Так «теги» стоят на одной
высоте с «тегами» второго языка. На экране уже 1100px колонки складываются в
одну.
