# Процесс публикации контента

## Этап 1. Подготовка инфраструктуры в Git

- [x] Создание ветки `posts_db` (ветка-сирота для хранения базы данных)
- [x] Инициализация файла `posts.yaml` на ветке `posts_db`
- [ ] Добавление секретов в GitHub: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
      `DISCORD_WEBHOOK_URL`

## Этап 2. GitHub Actions workflow

- [x] Файл `.github/workflows/publish.yml` создан
- [x] Триггер: push в `main` с фильтрами `src/posts/**`, `src/projects/**`,
      `src/weekly/**` + `workflow_dispatch`
- [x] Загрузка `posts.yaml` из ветки `posts_db` перед запуском скриптов
- [x] Передача списка изменённых файлов через env vars `CHANGED_FILES` /
      `ADDED_FILES`
- [x] Сохранение `posts.yaml` обратно в `posts_db` с `if: always()`

## Этап 3. Шаблоны сообщений (`scripts/templates.json`)

- [x] Шаблон для постов: "Выложен новый пост: {title}\n\n{excerpt}\n\n{url}"
- [x] Шаблон для проектов: "Добавлен проект: {title}\n\n{description}\n\n{url}"
- [x] Шаблон для итогов недели: "Итоги недели\n\n{excerpt}\n\n{url}"

## Этап 4. Скрипт подготовки (`scripts/prepare-post.js`)

- [x] Определение типа контента по пути файла (posts/projects/weekly)
- [x] Парсинг env vars и фильтрация `.md` файлов из трёх папок
- [x] Валидация: 0 файлов → выход, N файлов → цикл обработки
- [x] Загрузка шаблонов из `scripts/templates.json`
- [x] Парсинг YAML-фронтматтера (произвольные поля)
- [x] Применение шаблона с подстановкой переменных
- [x] Сохранение trimmed версий в `publish/{дата}.md`
- [x] Сохранение `socialText` (готовое сообщение) в `.post-meta.json`

## Этап 5. Скрипт публикации (`scripts/publish.js`)

- [x] Чтение `socialText` из `.post-meta.json` (без чтения publish/ файлов)
- [x] Цикл обработки элементов
- [x] Загрузка и парсинг `posts.yaml`
- [x] Новый контент: `sendMessage` в Telegram + POST в Discord → сохранение IDs
- [x] Существующий: `editMessageText` в Telegram + PATCH в Discord
- [x] Обработка ошибок редактирования
- [x] Задержка 1с между отправками при нескольких элементах (rate limit)
- [x] Запись обновлённого `posts.yaml`

## Этап 6. Документация

- [x] `publish.md` — описание процесса (алгоритм без кода)
- [x] `todo.md` — обновлён под текущую реализацию

## Этап 7. Тестирование

- [ ] Проверка поста: запушить новый пост → шаблон "Выложен новый пост" + запись
      в `posts.yaml`
- [ ] Проверка проекта: запушить новый проект → шаблон "Добавлен проект" +
      запись в `posts.yaml`
- [ ] Проверка итогов недели: запушить weekly → шаблон "Итоги недели" + запись в
      `posts.yaml`
- [ ] Проверка редактирования: изменить контент → сообщение отредактировано на
      обеих платформах
- [ ] Проверка чистоты: ветка `main` не содержит коммитов от `posts.yaml`
